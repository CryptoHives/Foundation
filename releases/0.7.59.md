# CryptoHives Foundation 0.7.59

*Released 2026-10-30 · tag `0.7.59.31593`*

This release adds breadth to authenticated encryption. **AES-GCM-SIV (RFC 8452)** joins the AEAD
set. GCM and CCM now run over the regional 128-bit block ciphers, and the GOST **MGM** mode
arrives along with the **Magma** block cipher. The three block cipher modes that `CipherMode`
declared but did not support (CFB, OFB and CTS) are now implemented. Secrets that used to remain
on the stack are now wiped before a method returns. The threading package gains an experimental
`AsyncReentrantLock`, and the analyzer package has been reworked onto control-flow data flow.

No public API is removed. Three bug fixes do change output, though: **CCM with nonces shorter
than 11 bytes**, the **Zeros / ANSIX923 / ISO10126 padding modes**, and **cSHAKE/KMAC with a long
customization string or key**. Data produced by earlier versions in those cases is affected, so
please read **Breaking and behavior changes** below before upgrading. The project is now licensed
**MIT OR Apache-2.0**.

## Highlights

### AES-GCM-SIV — nonce-misuse-resistant AEAD (RFC 8452) (#315)

`AesGcmSiv128` and `AesGcmSiv256` derive from an abstract `AesGcmSiv : IAeadCipher`. Keys are 16 or
32 bytes (the RFC defines no 192-bit variant), the nonce is 12 bytes and the tag is 16 bytes. .NET
has no in-box AES-GCM-SIV, so this package is the only way to get it on every target framework down
to net462.

A repeated nonce reveals only whether the same (associated data, plaintext) pair was sealed twice.
Unlike AES-GCM, it does not leak plaintext or allow forgeries. A unique nonce per message is still
the intended use.

```csharp
using var siv = AesGcmSiv256.Create(key);
byte[] sealedData = siv.Encrypt(nonce, plaintext, associatedData);   // ciphertext || tag
byte[] opened = siv.Decrypt(nonce, sealedData, associatedData);
```

- Per-message key derivation and CTR reuse the existing scalar, AES-NI and ARM AES cores. AES-NI
  and ARM run CTR four blocks at a time.
- **POLYVAL** uses a native PCLMULQDQ multiply on x86. The scalar path goes through GHASH's Shoup
  table via the byte-reversal relation of RFC 8452 Appendix A. Arm64 uses scalar POLYVAL for now.
- Per-message keys and schedules are erased. A failed decryption zeroes the output. In-place
  encryption and decryption are supported.

### GCM and CCM over the regional block ciphers (#314)

| Class | Key sizes | Used by |
|---|---|---|
| `Sm4Gcm`, `Sm4Ccm` | 128 | TLS 1.3 suites of RFC 8998 |
| `AriaGcm`, `AriaCcm` | 128/192/256 | GCM in TLS (RFC 6209) |
| `CamelliaGcm`, `CamelliaCcm` | 128/192/256 | GCM in TLS (RFC 6367), CCM in IPsec (RFC 5528) |
| `SeedGcm` | 128 | |
| `KuznyechikGcm` | 256 | Interop only. Kuznyechik's national AEAD is MGM, below |

For ARIA and Camellia, the key length selects the variant, and `AlgorithmName` reports it (for
example `ARIA-256-GCM`). All of these classes derive from the new public `GcmCipher` and
`CcmCipher` bases, which cannot be derived from outside the library. GHASH keeps its
PCLMULQDQ/PMULL tiers, and the block cipher runs its managed implementation. **The AES paths are
unchanged:** for a non-AES cipher the AES SIMD branches and the fused AES pipeline cannot be reached.

### Kuznyechik-MGM, Magma and Magma-MGM — the GOST AEAD (RFC 9058, RFC 8891) (#333)

MGM, the Multilinear Galois Mode of RFC 9058, is the AEAD that GOST TLS 1.3 (RFC 9367) and GOST CMS
use. It is now available over both GOST R 34.12-2015 block ciphers:

| Class | Block | Nonce | Tag | Notes |
|---|---|---|---|---|
| `KuznyechikMgm` | 128 | 16 bytes, top bit clear | 4–16 bytes | |
| `MagmaMgm` | 64 | 8 bytes, top bit clear | 4–8 bytes | Plaintext + AAD below 2³² bits |
| `Magma` | 64 | | | New block cipher (RFC 8891), ECB/CBC/CTR |

- The tag length is chosen by the length of the tag buffer. The `byte[]` overloads use a full
  block. Decryption checks the tag before decrypting.
- RFC 9058 is followed strictly, as `pygost` also does: a nonce with its top bit set, and an empty
  plaintext together with empty associated data, both throw `ArgumentException`, as does Magma
  input past the 2³²-bit limit.
- The carry-less multiply has three tiers: PCLMULQDQ, ARM PMULL, and a constant-time scalar
  version. Every block is multiplied by a fresh H, so nothing can be precomputed as it can for
  GHASH. Products are summed unreduced and reduced once per message.
- Like the other table-driven ciphers here, **`Magma` is not constant-time against cache
  attacks.**

### CFB, OFB and CTS — the remaining `CipherMode` values (#323)

`CipherMode.CFB`, `OFB` and `CTS` now work, and their `[Obsolete]` markers are removed. ARIA,
Camellia, Kalyna, Kuznyechik, SEED, SM4 and AES all get the three modes. AES's dedicated ECB/CBC/CTR
paths are unchanged.

- **CFB:** the segment size is `FeedbackSize`, which defaults to 8 bits as in-box. Padding applies
  to the segment size, as in-box.
- **OFB:** a stream mode like CTR, so padding is ignored.
- **CTS:** CBC-CS3 (RFC 3962). Input must be at least one block, and padding is ignored. When
  streaming, the last two blocks are withheld until the final transform, and in-place buffers are
  safe.

## Security

### Secrets wiped from the stack (#334, #335)

Key-schedule temporaries are now erased with `CryptographicOperations.ZeroMemory` before the method
returns, for AES, ARIA, Kalyna and Kuznyechik. The same applies to:

- ChaCha state, HChaCha20 subkeys and one-time Poly1305 keys;
- ML-KEM seeds;
- the HMAC hashed long key, the CMAC subkey seed and the KMAC padded key;
- the AES key-wrap plaintext;
- GHASH/J0/ICB, CBC-MAC state, keystream and expected tags.

Round-key wipes that used `Clear()` now use `ZeroMemory`. This closes the internal sweep tracked in
#294.

Every method with a `stackalloc` is now `[SkipLocalsInit]`, and the buffers that relied on
implicit zeroing clear themselves explicitly. One example is the ML-DSA `rnd = 0³²` seed used for
deterministic signing.

`ZeroMemory` keeps `NoInlining`, which is what stops the compiler from deleting the wipe as a dead
store, but it no longer runs unoptimized. That makes the extra wipes cheap (#335). Wipes of values
that are public by construction are dropped.

### AES key unwrap left the key behind on failure (#334)

When the integrity check of an AES key unwrap failed, the unwrapped key stayed in the output
buffer. Unwrap now works in a stack buffer up to 512 bytes, and a pooled one beyond that. The buffer
is wiped in a `finally`, so a failed check leaves nothing behind.

## Threading

### `AsyncReentrantLock` — an experimental reentrant async lock (#249)

`AsyncReentrantLock` is an async exclusive lock that allows nested acquisition. That covers nesting
across awaited calls, and fire-and-forget work started while the parent still holds the lock. It
keeps one `AsyncLock` per nesting depth, and an `AsyncLocal` records which depths the current async
flow holds. Siblings at the same depth serialize, and unrelated callers queue on depth 0.

```csharp
var mutex = new AsyncReentrantLock();

using (await mutex.LockAsync(cancellationToken))
{
    using (await mutex.LockAsync())   // nested on the same flow: no deadlock
    {
    }
}
```

It is meant for porting reentrant `lock`/`Monitor` code, for layered APIs where one locked method
calls another, and for callbacks that re-enter a locked API. **Reach for it only when `AsyncLock`
cannot be made to fit.**

It ships marked `[Experimental("CHTEXP001")]` on .NET 8 and later, so using it is a compile error
until you suppress `CHTEXP001`. The error links to the docs page.

Known limitations:

- **Wrapping `LockAsync` in an `async` method hides the hold from the caller**, so the caller's
  next nested acquisition deadlocks. This follows from tracking depth through `ExecutionContext`.
  The new analyzer rule CHT013 reports it at compile time.
- **A started child task and its parent are peers**: both run code under the same hold.
- **A nested fire-and-forget holder that never finishes keeps the lock held**, the same trade-off
  as with `Monitor`.
- **Nesting depth is capped** at `maxDepthLocksCapacity` (32 by default). A call past the cap
  throws `InvalidOperationException`, so runaway recursion fails fast.
- **Each acquisition allocates** two small objects, plus an async state machine when contended.
  There is no `TryLock` and no synchronous API.

## Analyzer changes (#249)

**New rule:**

| ID | Severity | Description |
|---|---|---|
| CHT013 | Warning | `async` method returns an `AsyncReentrantLock` releaser (hides the hold; nested acquisition deadlocks) |

CHT013 covers `async` methods, local functions and lambdas. It is registered only when the
compilation references `AsyncReentrantLock`.

**Reworked rules.** A review found false positives that broke consumers' builds, code fixes that
left code that didn't compile, and a rule (CHT007) that never fired. All of these are fixed:

- **CHT001/CHT010 now run on control-flow data flow.** One await per `if`/`switch`/`?:` branch, or
  one after reassignment, is no longer reported. Loops, parameters, `await vt + await vt` and
  `await (c ? vt : other)` now are. Lambdas and local functions get their own graph, so their own
  parameters and locals are no longer reported as captures, while local-function captures now are.
- **CHT002/CHT008** see through `ConfigureAwait` and expression-bodied lambdas.
- **CHT003** exempts `readonly` fields that hold reusable completed values.
- **CHT007** is reimplemented: a `Task` from `vt.AsTask()` that is awaited once, later in the same
  block.
- **CHT009** is reported only when Threading is referenced. Its fix rewrites
  `WaitAsync`/`try`/`finally Release()` into `using (await LockAsync())`.
- **CHT011/CHT012** count `await foreach` and `await using` as awaits.
- **Fix providers** handle every diagnostic they are given and offer `await` only in async code.
  They also insert `AsTask()` before `ConfigureAwait`, and no longer apply a local function's fix to
  its enclosing method.

## Bug fixes

### Cryptography

- **CCM with nonces shorter than 11 bytes (#326).** The length field and block counter were shifted
  as 32-bit values, so from the fifth byte onward the low byte was written again instead of zero.
  For 8–10-byte nonces this produced ciphertext and tags that no other CCM implementation accepts.
  For 7-byte nonces, every message threw "Message too large". Nonces of 11–13 bytes, which RFC 3610
  and most protocols use, were never affected.
- **Padding modes (#323).** `PaddingMode.Zeros`, `ANSIX923` and `ISO10126` were accepted but
  encrypted as PKCS#7. Padding now goes through one helper with in-box semantics, and the
  constant-time check is kept.
- **cSHAKE128/256 and KMAC (#334)** gave wrong output when the customization string, or the KMAC
  key, was longer than the rate. `bytepad` then ran in a pooled buffer whose zero-padding tail was
  never cleared.
- **Big-endian (#332).** BLAKE3 (chunk and XOF output) and Streebog gave wrong output on big-endian
  hosts. The new s390x CI run found both.
- **Poly1305 on Mono (#332).** The Mono JIT miscompiles the comparison carries on field-held state
  (s390x and ppc64le). Every call site now passes the accumulator in locals.
- **KangarooTwelve and `IncrementalParallelHash` no longer retain the message (#304).** Both are
  now O(1) in the input. Each chaining value is absorbed as its chunk completes. This also removes
  an `int` overflow past 2 GiB in KT, and the grown buffer that a pooled instance kept for its
  lifetime. Closes #236.
- **`RandomNumberGenerator`** now throws `ObjectDisposedException` after `Dispose()` instead of a
  `NullReferenceException` (#330).

### Performance

- **Hot loops (#331, #337).** The new internal `BinaryStore` (the counterpart of `BinaryLoad`) and
  `BinaryOperations` replace partial writes staged through temporary buffers or byte loops. They
  work on `ref` access, so loops carry no per-element range check. Applied across SHA-2, SHA-1, SM3,
  Whirlpool, Keccak, the ML-KEM and ML-DSA NTTs, and the cipher cores. Legal key and block size
  tables are now shared between cipher instances.
- **GCM and CCM block loops (#334)** process whole blocks without a per-iteration length check and
  handle the partial block once. CCM's CBC-MAC XORs whole blocks straight into the MAC state.
- **`ZeroMemory` is cheaper (#335)**, as described under **Security**.

## Breaking and behavior changes

> ⚠️ **CCM with an 8–10-byte nonce now produces standard output.** Data sealed with such a nonce by
> an earlier version only opened with this library, and it does **not** open with this version.
> Decrypt such data with the earlier version and seal it again. 7-byte nonces, which always threw
> before, now work. Nonces of 11–13 bytes are unaffected.

> ⚠️ **`PaddingMode.Zeros`, `ANSIX923` and `ISO10126` now pad as their names say.** Ciphertext
> produced with them by an earlier version was PKCS#7-padded. Under `Zeros`, decrypting it now
> leaves the padding bytes in place; under `ANSIX923` it fails the zero-fill check. `ISO10126`
> checks only the length byte, so its old ciphertext still decrypts. The new output matches the
> in-box `Aes`. `PKCS7` and `None` are unaffected.

> ⚠️ **cSHAKE and KMAC output changes when the customization string, or the KMAC key, is longer
> than the rate** (168 bytes for the 128-bit variants, 136 for the 256-bit ones). The previous
> output was wrong and could vary from call to call. Shorter inputs are unaffected.

> ℹ️ **License: MIT OR Apache-2.0** (#321). From this release the packages are offered under
> either license, at your option, following the Rust ecosystem's convention. Apache-2.0 adds an
> explicit patent grant, and MIT stays available. Releases up to 0.7.37 remain MIT. Both license
> texts ship in every package. Contributions now use the DCO instead of a CLA (#318).

> ℹ️ **The analyzer rework can report new findings.** CHT001 and CHT010 now catch consumptions in
> loops and through parameters, and CHT008 sees through `ConfigureAwait`. Builds that treat
> warnings as errors may need to fix or suppress them. The rework also removes false positives.

## Benchmarks and infrastructure

- **Mono runtimes workflow (#332).** It runs the Cryptography suite monthly, or on demand, on
  **s390x**, **ppc64le** and **wasm**. s390x is big-endian and the only place the
  `!BitConverter.IsLittleEndian` branches execute. The two hardware targets run under QEMU, and
  wasm runs on Node.js. A small in-process NUnit host replaces VSTest, which cannot run there.
- **ACVP full-vector workflow (#325).** The weekly run now passes absolute vector paths, and it
  compares regenerated selections by decompressed content, since deflate output differs between
  zlib builds.
- **Benchmark trends (#319, #324).** Single-date selections group their bars by size, and sizes are
  now ordered numerically instead of as text. The serial Blake3.Managed row now sits under BLAKE3,
  where it had shown up as its own algorithm. Allocations reported in KB/MB now parse. Each SIMD
  tier is now a single series named after its .NET intrinsics class.
- **Tests.** The SIMD variant handling in the cipher and hash tests is unified (#315). Tests that
  need in-box algorithms browser-wasm lacks skip there.
