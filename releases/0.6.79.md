# CryptoHives Foundation 0.6.79

*Released 2026-08-12 · tag `0.6.79.4022`*

This release adds a new threading primitive, `AsyncKeyedLock<TKey>`, fixes a deadlock and several
lock-ordering defects across the async primitives, and brings ARM SHA-1 hardware acceleration to the
cryptography package. It also corrects a large amount of documentation that did not match what the
libraries actually do.

Two behavior changes and one analyzer API removal are listed under **Breaking and behavior changes**
below — please read that section before upgrading.

---

## Highlights

### `AsyncKeyedLock<TKey>` — a pooled per-key async exclusive lock (#220)

Operations on different keys run fully concurrently; operations on the same key are serialized. The
lock is **not** recursive.

```csharp
private readonly AsyncKeyedLock<string> _locksByAccount = new();

using (await _locksByAccount.LockAsync(accountId, ct).ConfigureAwait(false))
{
    // Only one operation per accountId; other accounts proceed in parallel
}
```

Public surface: `LockAsync(key, ct)`, `LockAsync(key, timeout, ct)`, `TryLock(key, out Releaser)`,
`Count`, `IsInUse(key)`, and a `Releaser` struct implementing `IDisposable`, `IAsyncDisposable` and
`IEquatable<Releaser>`. The constructor accepts an optional `IEqualityComparer<TKey>`, a custom pool,
`maxIdleEntries` and `maxRetainedWaiters` (both default to 128).

**Allocation behavior.** The common path is allocation-free. Released keys stay mapped as *idle*
entries rather than being torn down, so repeatedly locking the same key allocates neither the entry
nor the dictionary node; past `maxIdleEntries` an unmapped key takes over the least recently idled
entry instead of allocating a new one. The contended path returns the waiter's `ValueTask` unchanged
rather than wrapping it in an `async` method, so a queued waiter costs no state-machine box.

**Where it does not win.** Two regimes are documented rather than hidden, both in the package README:

- **Many threads on disjoint keys** — the administrative lock is taken on every acquire and release,
  so its contention scales with total instance throughput rather than per-key demand. A separate
  sharded type is the planned fix and is deliberately not part of this release.
- **Working set larger than `maxIdleEntries`** — every acquisition misses, the entry-reuse advantage
  is gone, and only the dictionary node remains.

Also adds `ValueTaskSourceObjectPools<TKey>`, a generic static giving one shared pool per closed key
type (the same technique `ArrayPool<T>.Shared` uses), because the non-generic pool holder cannot
carry a pool whose `Releaser` is generic over `TKey`.

### ARM SHA-1 hardware acceleration (#221)

`SHA1` gains an Arm64 SIMD implementation using the ARM SHA-1 crypto extensions, selected
automatically at runtime via the new `SimdSupport.ArmSha1` capability flag. As with every other
implementation in this package, the managed fallback keeps results identical where the hardware
path is unavailable.

## Bug fixes

### Threading

- **`AsyncBarrier` deadlock (#214).** The user-supplied post-phase action ran while holding the
  internal spin lock. That lock is built for critical sections measured in nanoseconds — waiters
  spin for roughly 40 µs before parking — and it is not reentrant. A post-phase action that
  cancelled a token belonging to one of the barrier's own waiters fired that registration
  synchronously on the same thread, re-entered the barrier through `RemoveWaiter`, and spun forever
  against a lock the thread already held. The same applied to `AddParticipant()` /
  `RemoveParticipant()` called from the action. `AsyncBarrier` now guards its state with a monitor
  and runs the post-phase action with no lock held; the phase advance and `PulseAll` happen in a
  `finally`, so an action that throws cannot wedge the barrier mid-transition.

- **Timeout timers were created inside the spin lock (#215).** `TimeProvider.System.CreateTimer`
  takes the runtime's process-global timer queue lock, and was being called while the primitives'
  internal spin lock was held. Timer creation now happens after the lock is released and before the
  cancellation registration — that order matters, because an already-cancelled token fires
  `UnsafeRegister` synchronously and can complete the waiter. Fixed in `AsyncLock`,
  `AsyncSemaphore`, `AsyncAutoResetEvent`, `AsyncManualResetEvent`, `AsyncCountdownEvent` and
  `AsyncBarrier`, plus all four paths of `AsyncReaderWriterLock`.

- **Zero timeout is now settled inside the lock, across all eight primitives (#220).** Several
  primitives checked `timeout == TimeSpan.Zero` immediately after the uncontended fast path. That
  denied a zero-timeout caller the retry every other caller gets after taking the lock — giving up
  on a lock the holder may have released in between — and it let a caller passing both a cancelled
  token and a zero timeout receive `TimeoutException`, which carries no token, rather than
  `OperationCanceledException`, which does. The check now sits after the retry and after the
  cancellation check in `AsyncLock`, `AsyncKeyedLock<TKey>`, `AsyncSemaphore`, `AsyncAutoResetEvent`,
  `AsyncManualResetEvent`, `AsyncCountdownEvent`, `AsyncReaderWriterLock` (4 sites) and
  `AsyncBarrier`.

- **`AsyncReaderWriterLock` checked the timeout before the cancellation token (#239).** Reordered so
  a cancelled token is observed first, with tests covering all four paths.

- **`AsyncAutoResetEvent` validated its timeout argument too late (#220).** Validation was folded
  into a branch below the fast path, so a negative timeout returned successfully when the event
  happened to be signalled and threw only when it was not. It now validates on entry like every
  other primitive. See **Breaking and behavior changes**.

- **Spin lock fell into the `Sleep(1)` trap too early under high contention (#213).** The spin
  threshold is raised from the default 20 to 200, with a separate code path for older target
  frameworks that do not support the parameter. Latency and cost tests were added.

- **The suggested replacement code used the wrong line endings (#241).** Fixes #222.

## Analyzer changes (#220)

**New rules:**

| ID | Severity | Description |
|---|---|---|
| CHT011 | Warning | `async` method only forwards an awaited ValueTask; return it directly |
| CHT012 | Info | `async` ValueTask wrapper boxes a state machine when it suspends |

CHT012 came directly out of the keyed-lock work — it is the diagnostic that would have flagged the
boxing that lock's contended path originally suffered from. Its code fix offers
`PoolingAsyncValueTaskMethodBuilder`, documented honestly as a partial mitigation: it pools the box
rather than eliminating it, and cannot reduce peak live objects.

**Retired rules:**

- **CHT004** (multiple `AsTask()`) — never reported. The rule had no detection code, and the
  scenario it named is already covered by CHT001, since `AsTask()` consumes a `ValueTask` exactly as
  `await` does.
- **CHT006** (ValueTask passed to `WhenAll`/`WhenAny`) — unreachable. The `Task` overloads take
  `Task`, so such a call does not compile, and the `ValueTask` overloads do not exist. The type
  system already enforced what the rule described.

CHT001's message was reworded from "awaited" to "consumed", to reflect that it also covers
`AsTask()`, `Preserve()` and `GetResult()`.

## Breaking and behavior changes

> ⚠️ **`AsyncAutoResetEvent.WaitAsync` with a negative timeout** now throws
> `ArgumentOutOfRangeException` unconditionally, instead of throwing only when the event was
> unsignalled. Code that relied on a negative timeout succeeding against a signalled event will now
> throw.

> ⚠️ **Re-entering `AsyncBarrier` from its own post-phase action** now throws
> `InvalidOperationException` instead of hanging. This matches what `System.Threading.Barrier`
> documents for the same situation. The old behavior was an unrecoverable deadlock, so this is
> strictly an improvement, but it does surface as an exception where code previously appeared to
> stall.

> ⚠️ **Analyzer package public API:** `DiagnosticIds.MultipleAsTask` and
> `DiagnosticIds.PassedToUnsafeMethod` are removed from the public `DiagnosticIds` class, following
> the retirement of CHT004 and CHT006.

## Documentation (#238, #233, #227, #232)

A sweep that corrected the published documentation against what the libraries actually do:

- **Cryptography memory footprint** — every row re-measured on x64/.NET 10 by walking each instance's
  fields and summing the static tables per declaring type. KT128/KT256 are not constant at all (they
  buffer the whole message), SHA3-224 contradicted its own formula, the pooled SHA-2 state arrays are
  twice the logical size, Kupyna holds four arrays rather than two, and several cipher and
  static-table figures were out by up to 7x. Missing HMAC/Poly1305/CMAC/GMAC rows were added.
- **Specs page** — ParallelHash ships (with vectors) but was listed as not implemented; BLAKE3
  derive-key does not ship but was documented with a factory method that has never existed (#237).
  Ascon is SP 800-232, not FIPS 207. The regional ciphers, Ascon-AEAD128 and the KDFs were added.
- **Package READMEs** — corrected sample code that did not compile against the shipping API
  (`Shake256.Create(outputBytes:)`, the cSHAKE parameter order, the HMAC
  `Update`/`Finalize`/`Reset` pattern), and documented the intrinsics actually used per architecture.

## Benchmarks and infrastructure

The benchmark pipeline was substantially rebuilt (#223, #224, #225, #226, #227, #228, #229, #232,
#233, #234):

- Benchmark runs for both Threading and Cryptography now live on a dedicated archive branch, keyed by
  the commit measured rather than the commit recording them. The trends database is generated at
  build time instead of being committed.
- The dashboards gained a Table mode (now the default), run-environment metadata, and an idempotent
  rebuild. Each run records the resolved version of every third-party library it measured against,
  and the framework it ran under.
- Fixed **Scaling by size**, which returned nothing for every family, and made it plot the run chosen
  in the Run picker rather than stitching together whichever run happened to be each series' latest —
  which could put a variant measured months ago on the same axes as one measured yesterday.
- New benchmark coverage: six keyed-lock classes (SingleKey, Cardinality, RollingKey, Concurrent,
  Multiple, TryLock), plus `AsyncSemaphoreMultipleBenchmark` (finally benchmarking the semaphore as a
  semaphore rather than as a mutex), `AsyncBarrierPostPhaseBenchmark` and
  `AsyncCountdownEventWaitersBenchmark`. Timed variants were added so every primitive supporting a
  timeout shows what arming a timer costs.

## Build and CI

- **New weekly workflow testing the packages published on nuget.org (#240).** Packages are validated
  at release time against freshly built artifacts, but nothing re-checked them afterwards — a moved
  or unlisted dependency, a new SDK or runtime the shipped assemblies do not work with, or a package
  that no longer restores would go unnoticed until a user hit it. The workflow runs Mondays and on
  demand, resolving the newest version all four packages share and testing that version's release
  tag across Threading/Memory/Cryptography × ubuntu/windows/macOS × net10.0/net8.0/net48.
- **.NET Framework build fix (#242).** The `AsyncKeyedLock` allocation tests used
  `GC.GetAllocatedBytesForCurrentThread`, which does not exist on .NET Framework; they are now
  compiled for the .NET targets only.
- Test tolerance raised in `SpinLockLatencyTests` to reduce flakiness (#216).
