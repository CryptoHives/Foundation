# CryptoHives Foundation 0.7.75

*Released 2026-11-14 · tag `0.7.75.50202`*

This is a maintenance release. It focuses on **BLAKE3** performance for inputs that are not a
whole number of SIMD batches, and on **CPUs with AVX2 but without AVX-512**. There, the 8-lane
kernels no longer run out of vector registers. That was a known issue in 0.7.59. It also fixes the
**Threading.Analyzers** bug that made `.editorconfig` severity settings for the CHT rules have no
effect.

No public API is removed and no output changes. `Streebog` gains two public constants.

---

### Known Issues

- Benchmarks: the SSSE3 and AVX2 rows measured on an AVX-512 host still use its 32 vector registers
  and single-instruction rotates, so they overstate the speed on real SSSE3- or AVX2-only hardware.
  The benchmark docs now say so, and `run-benchmarks.ps1 -DisableIsa AVX512` measures the narrower
  instruction set on the same machine.

## Highlights

### BLAKE3: partial batches, tails and AVX2-only hosts (#342)

BLAKE3 hashes 1024-byte chunks in SIMD batches of 16 (AVX-512), 8 (AVX2) or 4 (SSSE3, NEON)
chunks. This release speeds up the chunks left over after the full batches, and the tree reduction
above them:

- **AVX2 without AVX512VL.** The 8-lane kernels used to spill a register on every rotate on
  16-register hardware. Three state words now wait in spare rows of the message buffer, which
  leaves a scratch register for the shift-or rotates. The stepped kernel is now selected on
  AVX512VL rather than AVX512F. Three and four chunks run as two pair-kernel calls instead of a
  full 8-lane pass.
- **Trailing partial chunk in a SIMD lane.** In one-shot hashing (`HashData`, `TryComputeHash`) a
  partial last chunk takes the next free lane of the last 16- or 8-lane batch for its complete
  blocks. Only its last 1..64 bytes are compressed serially. No load reads past the input.
  Incremental `AppendData` is unchanged, because more data may follow.
- **One chunk plus a partial chunk on AVX2**, the leftover at sizes such as 10000 or 100000 bytes,
  now runs as one pair-kernel call instead of serially.
- **9..15 chunks on AVX-512** run in a single 16-lane pass.
- **Tree reduction.** The chaining values of a partial batch go through the 8-wide parent kernel
  and are pushed as complete subtrees instead of chunk by chunk. Single parent compressions take an
  SSSE3 path without a staging buffer.
- **SSSE3** batches 2 chunks on CPUs with the 32-register file (AVX512VL) and 3 otherwise.

On a Xeon E-2136 (AVX2 only) 3 KB and 4 KB inputs run about a quarter faster, and 10000 to
12288 bytes 11–14% faster. On a Zen 4 host a 10000-byte input runs about a fifth faster on the
AVX-512 and AVX2 tiers, and a 2 KB input about a fifth faster on SSSE3. The PR has the full
figures. Output is unchanged: a new test cross-checks every SIMD tier against the scalar tier for
1–16 chunks with tails of 0 to 1023 bytes.

## Bug fixes

### Threading.Analyzers

- **`.editorconfig` severity for the CHT rules is honored (#340).** Every rule carried the
  `CustomSeverityConfigurable` tag, which tells the compiler that the analyzer manages severity
  itself, so `dotnet_diagnostic.CHTxxx.severity` entries were ignored. CHT002 set to `none` still
  fired, and the Info-level CHT009 could not be raised to a warning. Closes #339.

---

## New features

- **`Streebog.HashSizeBytes256` and `Streebog.HashSizeBytes512` (#353)** name the two output sizes
  (32 and 64 bytes).

## Breaking and behavior changes

> ℹ️ **CHT severity settings now apply.** A project that set a CHT rule to `error` in
> `.editorconfig` now gets that error, and one that set a rule to `none` no longer sees it.

## Benchmarks and infrastructure

- **Benchmark scripts (#345, #350).** `update-benchmark-docs.ps1` now publishes the AesKeyWrap and
  AsyncReentrantLock reports, and no longer warns about reports that are excluded on purpose. The
  reentrant and leaf AsyncReentrantLock benchmarks use distinct categories, so their rows no longer
  overwrite each other in the trends database. A new `-Comment` parameter records run settings that
  the reports do not capture, such as the power plan. On macOS, `run-benchmarks.ps1` keeps the host
  awake for the whole run.
- **Tests (#355).** More test fixtures run in parallel. A guard test fails when a fixture states no
  parallelism.
- **Code cleanups (#351, #352).** Code-analysis warnings in the ciphers and hashes are fixed. The
  single-word pointer writes moved from the internal `BinarySpans` to `BinaryStore`. Neither
  changes behavior.
