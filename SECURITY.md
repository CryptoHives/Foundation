# Security Policy

Thank you for helping to keep **CryptoHives Open Source Initiative** and its ecosystem secure.

We take the security of our software seriously.  
If you discover a potential vulnerability, please report it responsibly using the instructions below.

---

## Reporting a Vulnerability

**Do not open public GitHub issues for security reports.**

Report it privately through GitHub's private vulnerability reporting:

👉 **[Report a vulnerability](https://github.com/CryptoHives/Foundation/security/advisories/new)** (or the **Security** tab of the affected repository → *Report a vulnerability*)

Only the maintainers can see the report. You can attach a proof of concept, discuss the fix with us in the same private thread, and be credited in the published advisory.

Please include:
- A detailed description of the vulnerability
- Steps to reproduce or proof-of-concept
- The potential impact and affected components
- How you would like to be credited, if at all

### No GitHub account?

Send a short note to **[security@cryptohives.org](mailto:security@cryptohives.org)** — **without** any vulnerability details — and we will invite you to a private advisory where they can be shared securely. We do not offer PGP-encrypted email.

---

## Responsible Disclosure Guidelines

We ask all researchers to:
- Avoid publicly disclosing details until a fix is released.
- Avoid actions that disrupt services or compromise user data.
- Respect the privacy of users and systems during testing.

We appreciate your contribution to the safety and trust of the CryptoHives Open Source Initiative.  
Together, we can keep the hives secure. 🐝

---

*This policy follows GitHub’s [Security best practices](https://docs.github.com/en/code-security/getting-started/adding-a-security-policy-to-your-repository).*
